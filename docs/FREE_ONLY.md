# 免费章节约束（FREE_ONLY.md）

> **本项目只用于免费章节。不得涉及任何关于 VIP 付费内容的抓取、解密、绕过或互补。**
>
> 这不是一句免责声明，而是**六层可验证的技术约束**。任何一层命中即拒绝，
> 且**没有「跳过开关」**。`python -m noveldown selfcheck` 可机械校验第 6 层。

---

## 六层约束

> **2026-09-20 重要修正（第 1 层）**
> 早期版本把「起点 / 纵横 / 17K / 晋江 / 刺猬猫 / 飞卢」整站拉黑，理由是"它们含 VIP 内容"。
> 那是**粒度放错了层级**：
>
> - 「**站点**含 VIP 内容」—— 几乎所有正版站都成立；一本小说通常前几十章免费；
> - 真正该拦的是「**该章节**需要登录 / 付费才能读」—— 这是**章节级**问题。
>
> 结果可用规则里只剩盗版站（3 条全是），而**正版免费平台反被拒之门外**。
> 现在站点层只保留「项目明确声明不支持」的政策旋钮（默认**空**），
> 拦截职责下沉到下面的第 3 / 4 层。

### 第 1 层 · 站点层：项目声明不支持的域名（政策旋钮，默认空）

`noveldown/constants.py::POLICY_DENYLIST` **默认是空的**——站点层不做"含 VIP 就拒"的技术判断。

这一层只回答一个问题：**项目是否主动声明不支持某域名**（例如出于运营策略）。
它与技术能力无关，因此默认不拦任何站点。

> **为什么不再拦付费站**：本站点层原本拒绝的域名里，起点、纵横、17K 等都属于
> 「正版 + 含免费章节」。把它们整站拒掉，等于放弃了正版来源。
> 它们真正的障碍是**技术性**的（WAF / 目录靠 JS），已在 `noveldown/rules/*.json`
> 里以**停用规则存根**的形式逐条记录原因，而不是笼统拉黑。

相似域名的判定仍做双向匹配（`host == d` / `endswith("." + d)` / `startswith(d)`），
防止 `example.com.evil.net` 这类绕过——该机制由 `tests/test_freeguard.py` 验证，
用的是临时填入的政策名单。

### 第 2 层 · 规则层：规则必须自证免费

每个**启用**的站点规则 JSON 必须含 `"free_only": true`，否则规则加载直接失败。
规则的 `demo_url` 也要过第 1 层名单（机制同上）。

停用规则（`"enabled": false`）是**调研记录存根**：只要求写明 `disabled_reason`，
不要求写全选择器——避免为一份说明堆几十行无用配置。
`find_rule()` 命中停用规则时会**报出停用原因**，而不是含糊地说"没有规则"。

### 第 3 层 · 目录层：VIP 标记章节不请求 ← **主防线**

站点层放宽后，这一层就是实际的主力。目录项命中
`VIP_ITEM_CLASS_MARKERS`（`vip` / `lock` / `paid` / `pay` / `price` / `coin` /
`charge` / `subscribe` / `vipchapter` / `vip-chapter`）或
`VIP_ITEM_TEXT_MARKERS`（只收**徽章形态**：`（VIP）`、`【VIP】`、`VIP章节`、
`会员专享`、`付费章节`、`需购买` …）时，该章标记 `status=locked`，
**不发起任何网络请求**。

比较**不区分大小写**（站点常写 `VIP`，标记词是小写——实测踩过这个漏检）。

> **class 表为何比文本表宽**：站点给目录项加 class 的意图很明确，
> 且 class 不会出现在正常章节内容里。实测纵横用 `class="pay fr"` / `user_pay`
> 标注付费章——原表的裸 `paid` 匹配不到，故补入 `pay` 等写法。

> **为什么标题文本只认「徽章形态」**（实测踩过）：早期把裸词「付费」「订阅」
> 也纳入文本匹配，结果一个正常章节「第3章 付费墙占位」被误锁成 `locked`——
> 标题里的普通词会把合法免费章节整批丢掉。因此文本匹配收窄到
> 「明显是徽章」的写法，而宽表只用于 class 判定。

### 第 4 层 · 正文层：付费墙特征 + 最小字数 ← **第二道防线**

抓到的正文命中 `PAYWALL_MARKERS`（`本章为VIP章节` / `订阅后可阅读` / `购买本章`
/ `余额不足` / `请先登录` / `试读结束` …）或字数低于 `MIN_CHAPTER_CHARS`(50) 时：

- 标记 `status=blocked`
- **正文立即丢弃**（内存里也清空）
- 落盘时只写状态与原因，正文段落写空数组

**特征词覆盖三类墙**：

| 类型 | 例子 | 说明 |
|---|---|---|
| 订阅 / 购买 | `本章为VIP章节`、`购买本章`、`余额不足` | 传统付费墙 |
| 登录 | `请先登录`、`登录后可阅读` | 需账号 |
| **APP 墙** | `APP内免费畅读`、`下载【`、`请在APP` | **2026-09-20 新增**。不少中文小说站是「APP 优先」，web 端只放前若干章；那些章的"正文"是 70+ 字的下载引导，**高于最小字数阈值**，不显式拦截就会被当成正常正文保存（实测七猫第21章：2 段 78 字） |

这一层是"目录没标、但正文其实是墙"的兜底。
**站点层放宽后，它和第 3 层共同承担原本由整站拉黑提供的保证**，
由 `tests/test_integration_guard.py` 端到端验证（断言受保护章节的 URL **从未被请求**）。

### 第 5 层 · 导出层：写盘前终检（查**泄漏**，不查存在）

`freeguard.assert_no_protected()` 在任何导出器写盘前调用，检查的是
**受保护章节不得携带正文**——而不是「不得存在受保护章节」。

> **为什么不能查「存在」**（2026-09-20 修正）：纵横那本书 705 章里有 650 章是 VIP，
> 目录层会把它们标成 `locked`（正文为空、永不请求）。这是**正常状态**。
> 若终检写成「存在受保护章节就拒绝导出」，那么任何含 VIP 的正版站都永远导不出来
> —— 又是把粒度放错了层级。
>
> 真正要防的是：`locked` / `blocked` 的章节**却带着正文**。那说明某一层拦截失效
> （目录标记没生效、或付费墙正文没被丢弃），此时必须**失败**而不是静默写进成品。

导出器另用 `filter_exportable()` 只取 `has_content` 的章节，
所以受保护章节既进不了产物，也不会因为"存在"而阻断整本书的导出。

导出器另外只接受 `has_content` 的章节（同时排除未抓取 / 抓取失败），
不会把空章塞进成品。

### 第 6 层 · 代码层：不存在凭据路径

全项目**不存在**任何 cookie / 登录 / 购买 / token / 付费墙绕过相关代码路径。
`python -m noveldown selfcheck` 用正则扫源码（跳过注释与测试样本）机械校验：

| 检测形态 | 含义 |
|---|---|
| `\bcookies?\s*[:=]` | cookie 变量 / 参数赋值 |
| `['"]Cookie['"]` | Cookie 请求头字段 |
| `\bset_cookie\b\|\bcookiejar\b` | Cookie 写入调用 |
| `--vip\b` | VIP 开关 |
| `\bpassword\b\|\bpasswd\b` | 口令字段 |
| `['"]token['"]\|\btoken\s*=` | token 字段 |
| `/login\b\|\blogin_by_\w*\b\|\bsign_in\b` | 登录路径 |
| `\bbuy_chapter\b\|\bpurchase\b\|\bpaywall_bypass\b` | 购买 / 绕过付费墙 |

运行结果（2026-09-20）：

```
novel-down 读书爬虫 v0.1.0 · 免费章节约束机械自检
==============================================================
检查目标：源码中不存在登录 / Cookie / 购买 / 付费墙绕过等代码路径。
扫描根目录：G:\repos\novel-down
--------------------------------------------------------------
结果：PASS —— 未发现任何凭据或付费相关代码路径。
```

## 对参考资料的取舍

参考资料里有多处直接涉及 VIP，本项目的处理是**取结构、弃语义**：

| 参考 | 涉及 VIP 的部分 | 本项目处理 |
|---|---|---|
| CSDN 139809090 | 标题即「可爬起点 **VIP** 内容」，代码内嵌账号 Cookie | 只取「生产者-消费者 + 线程池」并发结构 |
| CSDN 136774768 | 用 F12 断点绕过起点调试保护以取 Cookie | 只取基础请求流程与请求头 |
| FictionDown | 起点正版信息 + 盗版正文**互补补齐 VIP 章节** | 只取「缺失/乱序校对」「广告过滤」「断点续爬」的检查维度，**未复制代码**（GPL-3.0） |
| novel-downloader | 登录 Token / VIP 参数 | 只取「规则驱动站点适配」的架构思想，**未复制代码**（AGPL-3.0 传染） |
| backupqidian | `--vip` 开关 + `cookies.txt` + `get_session()` | 只取「起点免费目录 API 存在性」这一事实，凭据路径全部排除 |

## 支持现状（2026-09-20 实测）

放宽站点层后，正版站的真实情况是**技术障碍**而非政策障碍：

| 站点 | 类型 | 免费章节 | 实测结果 |
|---|---|---|---|
| **七猫免费小说** | 正版·免费阅读 | 708 章里 20 章 | ✅ **已支持**。目录接口逐章带 `is_vip` → 688 章标记 locked、**零请求**；20 章 43 065 字 |
| **纵横中文网** | 正版·含 VIP | 705 章里 50 章 | ✅ **已支持**。目录项带 `class="vip col-4"` → 650 章标记 locked、**零请求**；50 章免费正文 163 576 字 |
| **番茄小说** | 正版·免费阅读平台 | 全站免费 | ✅ **已支持**。字体反爬（正文 54% 字符是 PUA 码位），靠字形轮廓匹配还原，362/362 命中 |
| 起点 | 正版·含 VIP | 前 ~20 章 | ⛔ 停用。**腾讯云 Chaos VM**：首页与子域均 202 + `x-waf-captcha-referer`，不下发会话令牌；无头 Chromium 等 42s 不放行且被识别为自动化。**非政策拒绝** |
| 17K | 正版·含 VIP | 部分 | ⛔ 停用。目录页仅 5.8KB，靠 JS 异步加载 |

停用原因逐条写在 `noveldown/rules/*.json` 的 `disabled_reason` 字段里，
`python -m noveldown sites` 会列出来。**它们都没有"因为含 VIP 所以不做"这一条。**

> **起点为什么不能像纵横那样做**：纵横的目录与正文都是**服务端渲染**的（纯 HTTP 可取），
> 本项目的第 3 层因此能在目录层就识别 VIP 标记。起点则是**先过 WAF 才给会话**——
> 那一步需要人机验证，属于需要人参与的环节，不在无人值守爬虫的范围内，
> 代码里也不做任何绕过。这与"含不含 VIP"无关。

## 使用者须知

1. **本工具只能抓取站点公开、无需登录即可访问的免费章节。**
2. 抓下的内容版权归**原作者与发布方**所有，仅供**个人离线阅读**，不得再分发或商用。
3. 请遵守目标站点的 robots 与服务条款；默认并发 4、基础间隔 1.2s±0.8s，
   遇到反爬状态码会自动全局降速（`RateLimiter.slowdown`）。
4. 若某站点整站以 VIP 章节为主，**本项目不予支持**，也不会为其添加规则。

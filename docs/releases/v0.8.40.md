# novel-down v0.8.40 —— 审计报告 P1(5) + P2(13) 全部处理完毕

> 本版是 **审计问题清零版**：上一版 `v0.8.39` 已经修了 GUI 导出崩溃 + 路径穿越，
> 这一版把审计报告里**剩余的 18 项**（P1 五项 + P2 十三项）全部处理掉，
> 其中一项（`#11`）经实测后**不采纳**并记录了理由。
>
> 测试 **288 → 353**（+65），门禁 **11 项 PASS + 自检 11/11**。

## P1（阻塞级，5 项全修）

- **#6 门禁过度声称**：`packaging/` 纳入门禁扫描；**顺带抓到审计报告也漏掉的真 bug**——
  门禁第 7 项的 `HARDCODED_PATH_RE` 对 `/Python314` 这类路径**一直失效**
  （`Python\d` + `\b` 在 `Python3` 后下一个字符是 `1`，同为 word 字符 → 没有词边界 → 匹配失败），
  而 `G:/assets`、`C:/Users` 这种行尾有边界的能中，于是「看起来门禁是活的」。
  → 改用负向先行断言 `(?![A-Za-z0-9_])`，注入测试证明现在能抓。
- **#4 目录静默 0 章**：`rules.validate()` 加载时强制校验 `catalog.id_from.pattern` 必须含
  `(?P<cid>…)`；`engine.discover()` 解析出 0 章时**显式抛错**并列出排查方向（不再静默通过）。
- **#3 GUI「停止」失效**：旧的「停止」是在进度回调里抛 `KeyboardInterrupt`，但
  `with ThreadPoolExecutor(...)` 的 `__exit__` 会 `shutdown(wait=True)`——异常也拦不住它等完
  所有已提交章节（审计实测 40/40 全抓完）。→ `engine.run(stop_event=...)` 协作式取消：
  `as_completed` 循环里 `break` + `shutdown(wait=False, cancel_futures=True)`，已在跑的章节自然收尾落盘。
- **#7 三模块零测试**：补 `http_client` / `ratelimit` / `identity_manager` 共 **28 个用例**
  （含限速器跨线程串行放行、重试语义、身份轮换、凭据字段不得出现等）。
- **#5 依赖未钉版本**：新增 `requirements.lock`（3 直接 + 6 传递，全部 `==` 精确版本，
  版本取自本机打包环境实测）。

## P2（13 项）

- **#8 字体反爬降级不干净**：`deps_available()` 不再吞掉 brotli 的 `ImportError`，缺 brotli 时
  如实报告「woff2 读不了」；`_font_decode` 加 `FONT_DECODE_MIN_COVERAGE=0.90`，
  覆盖率低于阈值**不还原**（避免半乱码正文被当 status=ok 导出）。
- **#9 `--selfcheck` 抽验 5/11 → 11/11**：每一项都注入假违规现场（路径类伪造 tracked、
  内容类建临时目录塞真文件），证明门禁不是死的。
- **#10 CLI 异常友好化**：缺 playwright 时抛的 `BrowserUnavailable` 不再裸抛 traceback，
  改返回退出码 6 + 明确告诉用户装什么。
- **#12 重定向 SSRF 纵深**：`http_get` 在每次重定向后校验目标主机，拒绝 RFC1918 内网段 +
  链路本地（169.254 云元数据）+ localhost，**放行回环 127.0.0.1**（本地合成站测试要用）。
  理由：SSRF 的价值在「借网络位置读内网服务」，这些段正是要害；不依赖站点白名单→不误伤跳转型站点。
- **#13 `.archived/` 第三方归档**：此前既不在 `.gitignore`、也不在门禁禁止目录——
  一次 `git add -A` 就能把 GPL/AGPL 源码带进 MIT 仓。→ 三处一起修：`.gitignore` 加 `.archived/`、
  门禁 `FORBIDDEN_DIR_PARTS` 加 `.archived/`、`docs/REFERENCE.md` 登记 8 个归档的体积 + SHA-256。
- **#14 curl_cffi 路径也清 cookie**：原来只清了 requests 的 cookie jar，与「无 Cookie」表述不符。
- **#15 付费墙判定过宽**：`PAYWALL_MARKERS` 的泛词（`打开APP` 等）对整章正文做子串匹配会误杀正常长章。
  → 拆强/弱两档：强信号保持整章匹配；8 个泛词**只在正文 ≤ 200 字时**才采信（墙约 80 字、正常章 1000+ 字）。
- **#16** `browser.stealth_js` 的「规则文件可携带浏览器内 JS」语义写入 `docs/REFERENCE.md`。
- **#17** README 说清门禁边界：「门禁保证不随仓分发第三方源码，不保证零行级借鉴」。
- **#18** 删掉仓库根的 `noveldown.spec` 残留；`tests/test_parser.py` 的 docstring 改 raw string
  → 全仓 `compileall -W error::SyntaxWarning` 现在完全干净。
- **#19 / #20** README 补 `--max-items` / `--report` 选项；onefile 启动耗时 47s → 约 40s（审计实测 39.7s）。

## ⚠ #11 —— 经实测**不采纳**审计建议（重要）

审计 #11 建议删掉 `freeguard` 的 `host.startswith(denied)`，理由是「`endswith(\".\"+d)` 已够挡子域，
`startswith` 没有安全增益」。**我删掉后 `tests/test_freeguard.py` 立刻报红**——政策名单要防的是
「相似域名绕过」：名单写 `example-bad.com` 时，`example-bad.com.evil.net` 既不等于它、也不以
`.example-bad.com` 结尾，删掉 `startswith` 就拦不住。**政策名单 fail-closed（宁可误拦）≠
规则匹配必须严格**，两处语义不同是**有意的**。已恢复并写明理由。
